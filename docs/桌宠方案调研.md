# 跨平台桌宠方案调研（结论：不另开 Electron）

## 问题

桌面版 DSH 的桌宠若走「原生透明置顶窗口」，需要额外跑一个 Electron/Chromium 实例，
内存占用大（+80~150MB），且每个平台各需一份二进制。是否存在更省、可跨平台的做法？

## 桌面壳的硬约束（已从 `resources/app.asar` 源码核实）

| 事实 | 依据 |
|---|---|
| 桌面版是**双进程**：Electron 主进程 `spawn` 独立 Node 宿主进程 | `lib/main.js`：`spawn(node, [... 'dsh-desktop-host/lib/index.js'], { stdio:[ignore,pipe,pipe,ipc] })` |
| **Host 半身跑在纯 Node 进程**，无 Electron API | 同上；`dsh-desktop-host` 只 `runProfile` |
| 主进程 IPC 是**封闭白名单** | 只有 `directoryPick` / `browserAcquire|Release` / `platform.*` / `windowsAppearance` / `windowsMenu` / `nativeThemeSet` 等，**无开窗通道** |
| 宿主→主进程的 IPC 只接受固定消息类型 | `child.on("message")` 仅处理 `ready` / `platform-session` / `shutdown-complete` / `fatal` / 受控 `controlRequests` |
| 渲染层 `window.open` 被一律拒绝 | 主窗口、登录窗、强制更新窗全部 `setWindowOpenHandler(() => ({ action: "deny" }))` |
| 宿主进程**自带 koffi（原生 FFI）** | `dsh-desktop-host/node_modules/koffi/`（含 `win32_x64/koffi.node`） |

→ **插件无法让宿主或主进程为自己开一个原生窗口。**

## 现有原生桌宠怎么做到的

`dsh-pet-live2d` 的做法是**自带独立二进制**：

- `dsh-pet-live2d`（主包）+ `dsh-pet-live2d-desktop-win32-x64`（9.2MB `bin/dsh-pet-live2d-desktop.exe`）
- 即：又一个 Electron 实例，且按平台分包发布

## 候选方案对比

| 方案 | 额外内存 | 跨平台 | 工程成本 | 能"站在桌面上" |
|---|---|---|---|---|
| ① `shell.overlay` 页面内悬浮层 | **0** | **全平台同一套代码** | 低 | 否（在窗口内） |
| ② 自带 Electron exe | +80~150MB | 差（每平台一份） | 高 | 是 |
| ③ Tauri / 原生小程序（Rust/C#/Python） | +10~30MB | 中（Tauri 跨平台，仍需各平台构建） | 高 | 是 |
| ④ 借桌面壳主进程开窗 | — | — | — | **不可行** |
| ⑤ koffi FFI 直接建窗口 | 低 | **差**（Win32/macOS/Linux 三套 API） | 极高 | 是 |

## 结论

**桌宠采用方案 ①：`shell.overlay` 页面内悬浮层。**

理由：

1. **零额外占用** —— 复用已开的渲染进程，不新增任何进程。
2. **天然跨平台** —— 桌面版（Windows/macOS/Linux）与网页版共用同一套代码。
3. **官方就是为这个场景设计的插槽**（`replaceRisk: none`，add-only）：

   > Frame-wide floating layer, above every column and outside their scroll containers.
   > **The layer itself is click-through — entries opt back into pointer events — so an
   > occupant never blocks the app underneath.** This is the additive seat for a
   > frame-wide surface of your own.

   - 层级在整个框架之上、各栏滚动容器之外 → 拖到哪都不会被裁切；
   - **默认穿透**，宠物本体才开 `pointer-events: auto` → 不会挡住界面操作（桌宠最易做错之处）。

4. 桌面版还白拿一个能力：原生标题栏配色由 preload 的 probe 自动跟随（`setTitleBarOverlay`）。

## 若将来确实要"站在桌面上"

推荐方案 ③（Tauri 独立小程序，托盘常驻 + 无边框透明窗），而非 ②（再跑一个 Electron）。
它与 DSH 通过宿主进程的 HTTP 路由或本地回环通信，插件本体仍只负责配置与资源。
该形态作为**独立插件**发布，不并入主题插件。
