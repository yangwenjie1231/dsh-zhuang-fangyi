feat(C12-C15): 设置导入导出 / 明暗分档预设 / 一键推荐组合 / 壁纸轮播

设置结构 v5 → v6。四个键都是**可选叠加**，默认值保证老文件升级后行为不变。

── C14 一键推荐组合 ────────────────────────────────────────────────
预设已经是「一整套视觉性格」，但配套壁纸、字体、纱的厚薄还得自己一个个调。
每套预设加一份 `combo`（壁纸/不透明度/字体/阅读宽度），设置页预设行下加按钮
一次套好。

组合**由宿主算、随 /themes 下发**（`presetCombos`）—— 客户端是自包含 bundle，
不能 import src/，否则又会多一份手抄副本（这个项目刚因为手抄清单漏掉 LICENSE
栽过一次）。

刻意不覆盖 enabled / scheme / rail / motion：前三个是功能与外观偏好，
`motion` 是**无障碍**设置，被一个「换风格」按钮改掉属于越权。
不自动触发（与「推荐壁纸只提示、不自动切换」同一原则）。

── C12 设置导入 / 导出 ─────────────────────────────────────────────
导出：`{_meta:{plugin,version,exportedAt}, settings}` → Blob 下载（URL 用完
revoke）。导入：file input → JSON.parse → POST /settings。

安全边界**只有一处**：宿主 `normalizeSettings`（白名单 + 夹取）。客户端不再
写一遍字段校验 —— 写两遍必然漂移。所以「导入恶意 JSON」在结构上就写不进坏值
（8 种坏输入归一化后都是合法设置的断言盯着）。另挡 64 KB（与宿主 readBody 一致）。

导入后若 accentHue 变了要 `reloadThemes()` —— 与 save 同一个坑（token 表是
宿主算好下发的，不重取就「选了色相没反应」）。

── C13 明暗分档预设（本批最需要小心的一项）──────────────────────────
「浅色用青、深色用墨青金」。**发现并修掉一个既有的半生效状态**：
`theme/change` 原先只调 `syncSchemeWallpaper`，不重跑 `applySettings` ——
所以切明暗时壁纸会换、配色/材质/代码高亮不会。分档启用后必须走完整
`applySettings()`。

实现要点：
· `presetForScheme(settings, scheme)` 作为**唯一**预设读取入口（已改 8 处）；
  测试里有一条「没有漏用 settings.preset」的断言，拿反例验过能抓到
  （把某处改回直接读会立刻 FAIL）
· 跟随系统（`scheme:'system'`）走 token 层时，单一预设的 `{light,dark}` 对
  表达不了「浅色 A / 深色 B」→ 新增 `composeSchemeOverrides` 按**值**拼表
  （light 取 A.light、dark 取 B.dark）
· 重入闸门 `state.applying`：固定明暗下 `applySettings` 会 `setTheme`，外壳
  会再 emit `theme/change` → 无限递归。闸门必须在**调用之前**置位
  （第一版写在事件回调里，那样挡不住 applySettings 自身被重入）
· 客户端不能 import src/，所以 `presetForScheme` / `hasSchemePresets` 有本地
  副本；测试拿同一组输入跑两边断言结果相等（防两份漂移）

默认 `presetLight`/`presetDark` 都是 `null`（跟随主预设）——**不能**默认成某个
具体预设，否则升级即静默改变所有用户的观感。

── C15 壁纸轮播 / 随机 ─────────────────────────────────────────────
四档（关 / 1 分 / 5 分 / 30 分）+ 顺序或随机。

· 复用 `applySettings()`（内部走 `syncSchemeWallpaper`）→ 交叉淡入（B6）与
  暗版分流（B9）自动生效。直接写 `--zf-art-src` 会绕过这两个（都是修过的坑）
· **不写盘**：轮换是会话内展示状态。写盘会有两个坏结果 —— 每次重启都换一张
  （用户以为设置被改了）、导出文件里混进一个随机值
· 随机**排除当前那张**（否则 1/8 概率原地不动，看起来像坏了）
· 页面不可见跳过一轮；`enabled=false` / `background='none'` 不轮播
· 卸载时 `stopRotation()` —— 不停的话停用插件后它仍会每 N 分钟写一次 DOM

── 测试 ────────────────────────────────────────────────────────────
933 → **999 项**（用例 79–82），清单自检 38 项，contrast 增加组合合法性检查。

三处**空转断言**在自测中被发现并修掉（都是「写了但永远不会失败」）：
· contrast 的「组合越权检查」：`recommendCombo` 是显式挑键构造返回值的，
  往规格里加 `motion` 会被静默丢掉 → 越权检查永远通过。改为断言**输出键集合
  恰好正确** + **源规格里也不许有**越权/无法识别的键（拿反例验过）
· 「没有漏用 settings.preset」第一版把 helper 函数体也算了进去 → 误报。
  改为按函数体行范围排除，且白名单写成精确正则并断言条数（6 条），
  这样新增漏用会失败而不是被放宽
· `composeSchemeOverrides` 不分档时必须返回**原表引用**（不复制），
  有断言盯着 —— 否则「不分档」路径会被悄悄换掉
